# Agent Foundry handoff

This file is the portable, version-controlled checkpoint. It must be updated at every
verified implementation boundary and before a handoff. Git records exact source changes;
this document records why they exist, how to verify them, and how to resume safely.

Machine-specific logs, generated performance evidence, Library records, and local paths
stay outside Git. `RESTART-HANDOFF.md` remains the detailed local forensic checkpoint and
is not deleted, but it is intentionally ignored because it contains local paths and test
details that should not be published.

## Current state

- Operations, Observatory, Library, Settings, secure session actions, Terminal, and the
  Windows WebView2 host are implemented.
- Library relevance defaults to 105 agent-related records; 39 excluded records remain
  recoverable in the local Library but are not committed.
- Headless application, package, JavaScript, native security, Terminal, and lifecycle
  checks pass.
- The Windows distribution is generated by `desktop/windows/package.py` and `dotnet
  publish`; `desktop/windows/dist/` is a release artifact, not repository content.
- Git was initialized on `main`. The first verified source checkpoint is commit `9f27a47`
  (`Initial Agent Foundry implementation`). Generated/private files were excluded before
  staging, staged names were reviewed, and the committed portable suite passed.

## Product decisions that must survive a handoff

- Provider-neutral observation is the core. Harness, model provider, and model are separate
  identities; Codex is the only fully implemented adapter today.
- Claude Code, Pi Agent, and Hermes appear only as honest unavailable placeholders until
  real adapters exist. Generic JSON remains read-only.
- Session instructions are explicit, capability-checked, confirmed actions. Reading local
  session files never becomes a control channel, and live Send is never tested implicitly.
- Terminal panes use real native processes with bounded buffers and lifecycle ownership.
  WSL, elevation, PATH-based executable discovery, shell argument strings, and detached
  descendants are excluded from the contained V1 security model.
- Custom shells require an absolute executable path and exact SHA-256 in local
  `terminal-profiles.json`; that file is never committed.
- Skills, workflows, templates, and handoffs are ordinary versioned files. No database or
  automatic self-edit/promotion loop is part of the current product.
- Existing user projects and skills are read-only sources. Agent Foundry may catalog them
  but must not rewrite them.
- The Observatory must communicate real work; decorative features that do not improve
  orientation, drill-down, or actionability should be removed or simplified.

## Pending verification

- Active, foreground Observatory rendering performance is not yet verified. Authorized
  attempt 06 used the corrected browser diagnostics and proved a stable Observatory
  document, foreground native window, focused browser, and active motion. It stopped before
  sampling because the native guard reported `native_occlusion:intersecting_window`.
  Cleanup passed with zero owned processes, listeners, or new fixture/cache directories.
  A read-only post-run audit found persistent full-screen NVIDIA Overlay windows, including
  a topmost transparent layered window, but the attempt did not record the offending HWND;
  treat that as the leading explanation, not proof. No attempt 07 is authorized.
- Live Send and real provider launches remain deliberate manual tests and require separate
  confirmation.
- Pixel-perfect visual polish remains deferred to a later design pass.

## Resume

1. Read this file, `README.md`, `docs/CONTRACT.md`, and `docs/HELP.md`.
2. Confirm `git status --short` is understood before editing; never discard unknown local
   work or ignored Library/session data.
3. Run the portable suites below.
4. Inspect ignored local `RESTART-HANDOFF.md` and retained evidence only when diagnosing a
   machine-specific result; do not add them to Git.
5. Continue from **Pending verification**, recording a new commit and updating this file at
   the next verified boundary.

Run the normal headless suites before changing behavior:

```powershell
py -3 -B -m unittest discover -q
py -3 -B desktop/windows/test_package.py
node test_operations.cjs
node test_observatory.cjs
node test_foundry_ui.cjs
node desktop/windows/terminal/test_terminal.cjs
```

Never commit local Library data, provider credentials, WebView profiles, terminal profile
configuration, captured session logs, or generated test evidence.

## Recovery limits

A GitHub clone restores product source, tests, portable examples, and this handoff. It does
not restore the user's local Library, imported records, provider/session logs, credentials,
terminal profiles, generated Windows distribution, or machine-specific evidence. Back up
those separately and privately when they become valuable; never solve that by committing
them to the source repository.
